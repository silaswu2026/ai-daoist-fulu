## 2. 视频生成与渲染（本机）

### 2.1 素材

1. **首帧／封面**：本机 `GenerateImage` 或 PIL／字体绘白底红字 1080×1920  
2. **符面中段**：白底红字三截结构图（头／中／尾对齐口播）  
3. **口播**：本机 `edge-tts`（推荐 `zh-CN-YunyangNeural`，rate `-12%`，pitch `-5Hz`）  
4. **黄条**：ffmpeg `drawbox` + `drawtext`（`#F5C518` + NotoSansCJK-Bold）硬烧

字体：`/usr/share/fonts/opentype/noto/NotoSansCJK-Bold.ttc`

### 2.2 气口真裁（禁止用 TIMING 数字假装）

对每句：

```bash
# 例：裁头尾静音后再拼显式 gap
ffmpeg -i clause.wav -af \
  "silenceremove=start_periods=1:start_silence=0.02:start_threshold=-35dB,\
   areverse,\
   silenceremove=start_periods=1:start_silence=0.02:start_threshold=-35dB,\
   areverse" \
  clause_trim.wav
```

- 句间显式 gap **≤0.35s**（实测 max ≤0.40）
- 片头 lead ≈0.25s；**片尾静音 CTA ≤1.5s**
- 钩口播 **≤3s**；第二句不占钩

### 2.3 时间线建议（EP0）

| 段 | 内容 | 约束 |
|----|------|------|
| A | 首帧动效 + 钩 + 前半口播 | 钩落在 0–3s |
| B | 符面进画（≤10s）+ 三截映射 | 中切约 6–8s 可 |
| C | CTA 静帧 | ≤1.5s |

画幅：**1080×1920 @30fps**（母版）；聊天试看可 540×960。

### 2.4 保险编码（聊天／手机必遵）

母版可 High；**发聊天前必须再出一版**：

```bash
ffmpeg -y -i INPUT.mp4 \
  -f lavfi -i "anoisesrc=color=pink:amplitude=0.003:sample_rate=48000:duration=DUR" \
  -filter_complex "[0:v]scale=540:960:force_original_aspect_ratio=decrease,pad=540:960:(ow-iw)/2:(oh-ih)/2,fps=30,format=yuv420p[v];\
[0:a]aformat=sample_rates=48000:channel_layouts=mono[a0];[1:a][a0]amix=inputs=2:duration=first:dropout_transition=0[a]" \
  -map "[v]" -map "[a]" \
  -c:v libx264 -profile:v baseline -level 3.1 -pix_fmt yuv420p \
  -preset veryfast -crf 23 \
  -g 30 -keyint_min 30 -sc_threshold 0 -bf 0 -refs 1 \
  -c:a aac -b:a 96k -ac 1 -ar 48000 \
  -movflags +faststart \
  /workspace/short-video/_watch_chat/NAME_chat.mp4
```

自检：

```bash
# moov 必须靠前（offset 近文件头）
# 关键帧约每 1.0s 一个；profile=Constrained Baseline
ffprobe -v error -select_streams v:0 -show_entries packet=pts_time,flags -of csv=p=0 FILE \
  | awk -F, '$2 ~ /K/ {print $1}'
```

**已知坑**：`_watch/` 里 EP0 曾链到 moov 在尾的 release → 手机打不开。发布前对 release 也要 `ffmpeg -c copy -movflags +faststart`。

1. 封面／首帧是否一眼想点进去  
2. 钩子是否够狠（符／道×AI）  
3. 看完是否热血沸腾或强烈想点链接  

- 通过：一句「过」+ 最打动的点  
- 不通过：没感觉的原因 + 可执行改法（首帧／节奏／黄条／片尾）

## 6. 卡首帧根因与硬规（2026-11-01）

**现象**：手机只见第一帧／第一页，后面卡住（各版本均可能）。

**根因**（已 ffprobe 验包）：
1. 不是「第一帧后没数据」——0–10s 包连续存在。
2. 静帧 JPEG 进 H.264 → 大量 **17–50B 空 P 帧**；部分机型解码停在首帧。
3. 误用 **yuvj420p / color_range=pc** 会加重。

**硬规**：
- 强制 `format=yuv420p` + `color_range=tv`（bt709）；**禁 yuvj420p**
- 聊天试看：**all-intra**（`-g 1` / `keyint=1`，无 B 帧）或保证每秒有实运动、P 帧体积正常
- 母版可用 `g=30`，但不得依赖空 skip 帧
- `+faststart`；禁止只修 moov 不重编码

可播样例：`_watch_chat/EP0-r6-playable.mp4` · 笔记：`v01-agent-fulu/PLAYBACK_ROOTCAUSE_r6.md`
